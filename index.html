End-to-end encrypted

Per-message keys derived from a room key that never touches a server. Frames are padded, so even their lengths stay quiet.

Peer-to-peer mesh

Messages hop directly between members. The hub can only help peers find each other — it can't read, store, or deliver a single word.

One shared room

Install, open, you're in. The first person ever to open the app created the room and its key; the community key gates who can join.

Rotatable keys

The room host can rotate the room key at any time. Each new key is sealed under the old one — only current members ever learn it.

Code-word rooms

Type a code at the door and you're in a room with everyone who uses the same word. The room is derived on each device — the word itself is never transmitted.

The app, live

How it works

Your identity is a keypair generated on your device — no accounts, no phone numbers. The only shared service is this address hub: a signed, expiring {peer → address} directory, plus a signed pointer saying who currently hosts the room. Peers verify every record themselves; the hub stores bytes it cannot forge and cannot read. When you open the app you prove knowledge of the community key, receive the room key sealed for you, and talk directly to everyone in the room — the relay path, if your network needs one, carries only ciphertext.

Status

Early development — M3 field trials. The hub API lives at /api/reg, /api/lookup/<peerId> and /api/room/<roomId>.
